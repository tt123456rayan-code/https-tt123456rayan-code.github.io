## القسم 2: قواعد المبيعات والعملاء المحتملين

### الفكرة الجوهرية
ما منبيع «خدمة تصميم» — منبني للعميل معاينة حقيقية بهويته قبل ما يدفع قرش، فبصير القرار عنده «أشتري شي شفته وعجبني» مش «أراهن على وعد».

### المرحلة 1 — اصطياد العملاء المحتملين
1. **قطاعاتHigh-Value بعمّان:** صالونات نسائية، مطاعم صاعدة (تقييم عالي + مراجعات قليلة)، حضانات، عيادات فردية (أسنان/جلدية)، مراكز تدريب صغيرة
2. **القطاعات المشبعة (لا تضيع وقت):** محامين، مهندسين، عيادات كبيرة، أكاديميات كبيرة
3. **الفلترة الذهبية:** تقييم 4.5+ وعدد مراجعات ملموس + ما عندهم موقع (فيسبوك/إنستغرام لا يُعتبر موقعًا)
4. اللي عنده موقع → استبعاد من عرض المواقع بس خليه بالجدول لعرض فيديو/سوشال

### المرحلة 2 — رسالة الافتتاح (قالب ريان المعتمد)
المعادلة: ملاحظة حقيقية عنهم ← فجوة مؤلمة (زباين بيدوروا وما بيلاقوكم) ← طلب صغير

**القالب:**
1. «مرحبا، معك ريان من حصن — وكالة رقمية بعمان.»
2. «شفت [اسم العمل] وحبيت أسأل: مين مسؤول عن الموقع أو التسويق الرقمي عندكم؟»
3. «سبب تواصلي بشكل سريع إنه لاحظت [ملاحظة حقيقية: التقييم/الفجوة الرقمية]… احنا هدفنا نساعد [القطاع] ترتب هالجزئية.»
4. «في دقيقتين مناسب اتصل فيك واحكيلك الفكرة، ولا بتحب/بتحبي أبعثلك ملخص هون أفضل؟»

**قواعد:**
- ولا كلمة عن السعر
- بالأردني الدافئ
- إثبات إننا شفناهم شخصيًا
- CTA سهل الرد بنعم
- بصيغة مؤنثة عند مخاطبة صالونات نسائية أو طبيبات
- حوّل كل رسالة لرابط wa.me برقم العميل والرسالة URL-encoded

**الإيقاع:** يوم 0 الرسالة → يوم 2 قيمة بدون سؤال (مثال شغل) → يوم 5 تذكير لطيف → وقّف. 4-5 رسائل يوميًا فقط، الأحد-الخميس 10ص-1ظ أو 7-9م.

### تأهيل العملاء
- يُستثنى من عرض المواقع كل عمل عنده موقع فعلي بدومين خاص
- صفحات سوشال أو رابط wa.me لا تُعتبر موقعًا → العمل يبقى مؤهلًا
- المستبعدون يبقون بالقائمة لعروض فيديو AI أو إدارة سوشال

### قطاعات عمّان (أثبتت أنها بلا مواقع)
صالونات التجميل النسائية، الباربر شوب، العيادات البيطرية، مراكز العلاج الطبيعي، المطاعم الصاعدة، الحضانات ورياض الأطفال، العيادات الفردية ومراكز الليزر.

### صيغة الأسعار
- كل سعر يُكتب «يبدأ من X»
- ممنوع نطاقات (150–200) أو رقم مجرّد
- على الموقع والعروض والمواد التسويقية

### تسليم المعاينات
- نسختان دائمًا: رابط عام يُفتح بدون تسجيل + PDF متعدد الصفحات يفتح على آيفون وأندرويد ويُرسل واتساب

## القسم 3: قواعد التصميم والمحتوى

### استخراج هوية العميل
- الهوية البصرية من مصادر العميل نفسه أولًا (إنستغرام/فيسبوك، إعلاناته، صوره وشعاره)
- لا فرض بالِت عامة أو هوية حصن

### ممنوع اختراع معلومات
- كل البيانات (اسم العمل، المالك، التخصص، الهاتف، العنوان، الساعات، الروابط، الاقتباسات) من مصادر حقيقية أو placeholder واضح
- تُجمّع كلها بملف Configuration واحد

### مستوى بريميوم إلزامي
المؤسس يرفض القوالب الأساسية «بدائي» — كل تسليم بصري لازم يكون:
- هيرو سينمائي بصور حقيقية/مولّدة عالية الجودة
- تايبوغرافي عربي فاخر
- أنيميشن عند التمرير
- تفاصيل تفاعلية (واتساب عائم، شريط إحصائيات)

### ممنوع الإيموجي كعناصر واجهة
- أزرار، كروت، فوتر، أسهم → أيقونات SVG خطية رقيقة inline موحّدة (stroke 1.7, currentColor)
- الإيموجي مسموح فقط بنصوص الكابشنات ورسائل السوشال/واتساب
- حتى ↗ و☎ بينعرضوا إيموجي عالآيفون

### ممنوع letter-spacing على النص العربي
- يقطع وصل الحروف
- التباعد للنصوص اللاتينية الصغيرة فقط (class منفصل)

### خطوط عربية فاخرة (Google Fonts)
- **Alexandria** — للعناوين
- **IBM Plex Sans Arabic** — للنصوص
- **Amiri** — للمسات السيرِف

### أنيميشن النص العربي
- **ممنوع** تقسيم النص لـspans على مستوى الحرف — يقطع وصل الحروف
- التقسيم بالكلمة فقط
- عند تقسيم النص: قصر المحدِّدات على الأبناء المباشرين (`.card > b`) ومنع flex/grid gap أو display:block على الحاوي

### بنية المواقع البريميوم
- عدة صفحات/أقسام مستقلة بشريط تبويبات ثابت (رئيسية، خدمات، كيف منشتغل، تواصل)
- لا صفحة واحدة طويلة بالسكرول فقط
- أكثر من فيديو + كل قسم متحرك بتفاعل عند السكرول

### التطوير بالإضافة لا الاستبدال
- عند ترقية صفحة/موقع قائم: ممنوع تعديل أو حذف الأصول والمحتوى الموجود
- التحسين إضافة فوق الموجود

### ترقية الهوية
- كل الصفحات الفرعية تُعاد بنفس الهوية الجديدة
- ممنوع بقاء صفحة بالتصميم القديم
- المحتوى والأسعار تُنقل حرفيًا

### الصفحات القديمة تبقى موصولة
- عبر تبويب بشريط التنقل + رابط بقسم التواصل + رابط بالفوتر
- ممنوع صفحة معزولة

### معاينات سريعة التحميل
- تُضغط كل الأصول قبل النشر (WebP، الهيرو بمئات الكيلوبايتات)
- أي صورة ثقيلة أو بطء = عيب بالتسليم

### مراحل مشاريع العملاء
بحث ← UX ← اتجاه بصري ← Prototype ← نظام تصميم ← تطوير ← QA ← Polish ← نقد ذاتي من 10 وتحسين ما دون 9
- ممنوع الكود قبل التصور البصري
- المطلوب تنفيذ لا اقتراحات

## القسم 4: المواقع السينمائية بفيديو سكرول

### الملفات المرجعية

- `delivery.md` — تدفق النشر والتسليم
- `troubleshooting.md` — جدول الأعطال والحلول

### الفكرة
فيديو hero واحد مولّد بالAI يُسحب مع السكرول — نزول = يتقدم، طلوع = يرجع — والكابشنات تتكشف بالفراغ حوله، وتحته صفحة حقيقية بمحتوى مقنع وCTA واحد. HTML + CSS + Vanilla JS، بدون frameworks.

### التكييف على أدواتنا
| الأصل | البديل |
|---|---|
| Higgsfield صور | GenerateImage (gemini-3-pro-image للفريمات، GPT Image 2 للوجو) |
| Higgsfield فيديو | GenerateVideo (Veo): firstFrameImage، extendFromVideo، referenceImages |
| Hostinger | PublishFilePublicly + GitHub Pages |

### المراحل
1. **الجاهزية:** ffmpeg وNode متوفرين
2. **محادثة التصميم:** الموضوع ولمين، الإحساس، المراجع، الأصول
3. **ابحث عن الزبائن الحقيقيين:** اقرأ مراجعات ومنتديات القطاع → كوبي بكلمات الزبائن → اعرض مفاهيم
4. **مستوى العمق:** Tier 1 (6 ثوانٍ) · Tier 2 (15-20 ث متسلسل) · Tier 3 (الموقع المُخرَج)
5. **صمّم الصفحة أولًا ثم storyboard الفيلم**
6. **ولّد الـhero ببوابات:** فريم بداية → فحص → موافقة → فيديو → فحص → ⛔ بوابة الفيديو
7. **عالج الأصول:** scrub encode بـ-g 8
8. **ابنِ الموقع:** الكوبي يُوصَّل حرفيًا
9. **افحص نفسك:** سكرينشوتات، flick test، أسوأ فريم، reduced motion
10. **انشر:** PublishFilePublicly أو GitHub Pages
11. **حلقة الصقل**

### محرك السكرب المعتمد: Canvas frames لا video.currentTime
- تسلسل فريمات JPEG على Canvas
- استخراج: `ffmpeg -i scrub.mp4 -vf "fps=12,scale=1600:-2" -q:v 5 fr/name-d-%03d.jpg`
- موبايل: `scale=840, q:v 6`
- حزمة ثنائية لكل مرحلة: uint32 count + uint32 lengths + bytes
- ميزانية: دسكتوب 3-6MB / موبايل 1-3MB
- delta-gate الرسم، k=0.22 للتنعيم

### القوانين الـ12 لفيديو الـhero
1. الحركة توافق السكرول
2. موضوع واحد، حركة متواصلة بلا قطع
3. اrefeed المسار، حرّر الجسد
4. خطّط للنهاية أولًا
5. اختار موضوعات سامحة (سوائل، ضباب، خيوط ضوء)
6. محور حركة عمودي преимуществًا
7. الكومبوزيشن للتخطيط
8. بيع عبور الحدود
9. لو في منتج: علّم أو اقترب
10. النص فوق الفوتاج يحتاج legibility
11. حسّن النص بمسافة السكرول لا بالثواني
12. الحرس الثابت: «no text, no logos, no lettering anywhere»

- **الموبايل:** فوتاج 9:16 مستقل لكل مرحلة — ممنوع قص الأفقي

## القسم 6: قواعد الأداء والتقنية والنشر

### السلاسة شرط قبول أساسي
أي تقطيع («بعلق») يُبطل التسليم كاملًا حتى لو التصميم ممتاز — الحل من الجذر لا بترقيع.

### الموبايل تفاعلي بالكامل
- مثل الدسكتوب (سكرول-سكرب، ظهور متدرج، لمسات)
- ممنوع نسخة مخففة — الموبايل أولوية أولى
- Canvas على الجوال: devicePixelRatio كامل (حتى 3x) وممنوع التغبيش

### النشر النهائي على hisnjo.tech
- لا على روابط المعاينة
- غلاف الـsandbox يجعل origin الصفحة null فتُرفض الأصول

### CORS والأصول
- أي أصل يُجلب بـfetch لازم على hisnjo.tech نفسه
- pub.hyperagent.com يخدم src مباشرة لكن بلا هيدرات CORS
- الصور والفيديو المُشار إليها بـsrc فقط تصلح من الـCDN

### رفع الملفات الثنائية لGitHub
- base64 → أجزاء ≤2.9MB → كوميتات <3.3MB عبر paramsFile
- الرفع المباشر يخرّب والحد ~4MB
- تحقق md5 إلزامي

### روابط النشر
- hyperagent.com/s/... غلاف iframe
- الرابط النظيف: pub.hyperagent.com/p/<token>
- إعادة PublishFilePublicly بعد كل تعديل وإلا يخدم نسخة قديمة

### التفويض عند التعطل
عند تكرار الرفض المؤسس يفوّض الإكمال حتى النهاية بدون أسئلة وسيطة («بر حالك وزبطه»).

### تكييف المهارات الخارجية
المؤسس يرفض الأدوات الخارجية اللي تحتاج تثبيتًا أو حسابًا — تكيّف المهارة بالكامل على أدوات المنصة واختر أفضل بديل دون سؤاله.

## القسم 7: مهارات الوكلاء والتعلم المستمر

### حلقة المولّد والمقيّم (إلزامية قبل أي تسليم)
1. المقيّم مستقل وبسياق نظيف: وكيل فرعي جديد يستلم الرابط الحي + الـrubric فقط
2. الـrubric (7 بنود، معيار 9+ لكل بند):
   - الهيرو سينمائي
   - التايبوغرافي العربي سليم
   - أيقونات SVG صفر إيموجي
   - الهوية من براند العميل
   - صدق المحتوى صفر اختراع
   - التفاعلية والحركة شغالة
   - الموبايل وRTL بلا كسور
3. حدود: عتبة 9/10 · حد أقصى 3 تكرارات · كل تكرار يعالج البنود الساقطة فقط

### التعلم المستمر
- **ملاحظة** (مرة) ← **غريزة** (تكرر مرتين ← CreateMemory) ← **مهارة** (سير عمل ثبت نجاحه ← CreateSkill)

- قواعد الصياغة: قاعدة واحدة لكل ذاكرة · صيغة قابلة للتطبيق الأعمى

### تنسيق الوكلاء الفرعيين

2. مدخل واحد، مخرج واحد
3. مراحل متسلسلة لا تُقفز
4. استرجاع تكراري بحد 3 دورات
5. مراجعة بسياق نظيف

### ذاكرة الجلسات
- شو نجح (قرارات + أرقام) / شو فشل (سبب بسطر) / شو باقي (خطوات بالترتيب)

- خزّن قبل الضياع

## القسم 8: ECC والأمن

### نموذج الهجوم
كل نقطة دخل سطح هجوم — رسائل، PDF، سكرينشوتات OCR، مراجعات PR، خوادم MCP، skills خارجية، الذاكرة.

### الثلاثي القاتل (Willison)
بيانات خاصة + محتوى غير موثوق + اتصال خارجي بنفس الجلسة = الحقن يصير تسريبًا.

### مبادئ Sandboxing
- افصل الهوية (حسابات وكيل منفصلة، توكنات قصيرة العمر)
- شغّل غير الموثوق بعزل بلا شبكة
- قيّد الأدوات والمسارات الحساسة

### تقييم المخاطر رباعي المحاور (ecc2)
خطر الأداة الأساسي + حساسية الملف + نصف قطر الانفجار + اللارجعة
- ≥0.80 حظر · ≥0.50 تأكيد · ≥0.30 مراجعة · أقل = سماح

### سياسة MCP
موصّل افتراضي واحد فقط (chrome-devtools)؛ الباقي skills تغلف CLI/REST.
